Your workspace.
Your backend.

The included Node.js server provides a JWT-authenticated SQLite API. The app runs locally without it; connecting an API enables shared records across devices.

1. Start the reference server

Install dependencies and build the app from the project folder, then enable the API:

pnpm install --frozen-lockfile
pnpm build
pnpm api:enable
pnpm start

The setup command creates a private .env and data/api-connection.json. Keep the connection file private; it contains your first-time server setup key.

2. Connect in the app

  1. Go to Data & connection.
  2. Choose Import API connection file and select data/api-connection.json, or enter your API URL and setup key manually. Enter a server password to create the first super admin; later connections use your server password.
  3. Select Test connection.
  4. Optionally initialize an empty backend with your local workspace. Existing backend records are always loaded unchanged.
  5. Select Connect & use API.

Use local signs out so you can unlock the separate local workspace. Mode changes never merge or delete data.

On another device, use the same single email-and-password sign-in form. For a separate static frontend deployment, set VITE_API_URL to the central backend URL ending in /api. Add teammates in Users & roles. Local passwords are not uploaded. Sessions expire in 30 minutes and are revoked on logout or account access changes.

Protect your sign-in with 2FA

Server users can open My profile → Two-factor authentication, confirm their password, scan an authenticator QR code and verify its six-digit code. Save the ten recovery codes before closing setup. The installation owner has the same option under Account security. When enabled, both server sign-in and connecting from a local workspace require the second verification step. Browser-local accounts must switch to server mode for independent 2FA enforcement. Password resets and account unlocks preserve 2FA.

3. Send customer quotations

Choose Enable API services to use email while keeping local storage, or connect remote storage as above. In Customer email, save your SMTP host, port, TLS mode, credentials and sender details. Choose Verify SMTP; this checks authentication without sending a message.

Open a quotation and select Email customer. Review the recipient, subject, message and PDF attachment, then send. The app reports mail-server acceptance and updates the quotation to Sent. It does not claim inbox delivery. Your provider must support authenticated SMTP.

4. Use your own backend

Implement GET /workspace and PUT /workspace. Both require a valid individual JWT session. Implement the authentication and user-management endpoints from docs/API.md as well. GET returns { "workspace": ... }, or null for an empty backend, plus an ETag. PUT receives the whole workspace with If-Match and must atomically reject stale writes with HTTP 412.

CORS must allow your exact frontend origin and the headers Authorization, Content-Type, If-Match, and expose ETag. Full object schemas are documented in docs/API.md in the source package.

Production settings

Use HTTPS, set an explicit ALLOWED_ORIGINS allowlist, store API_TOKEN as a deployment secret and DATA_DIR on a persistent volume. Bind to HOST=0.0.0.0 only behind your HTTPS proxy. Back up the SQLite database, jwt.key, and email.key together. See the included README for complete setup and security boundaries.
